kortex Palette Redesign
kortex 0.8.0 · design study · 19 November 2026

Where should the agent talk to you?

Today kortex holds the whole conversation inside KRunner's result list. This page looks at four other answers, from a tidier palette to a session that stays beside your work, each as a prototype you can click through. The request is the same in all five: “why is my wifi so slow?”, two changes to allow, one answer.

What the popup has to survive

These limits come from KRunner itself and from the test rounds of 9–10 and 13 November. Each redesign below answers some of them and gives up something else.

KRunner pulls, it is never toldkortex re-runs the query over D-Bus with a word joiner (U+2060) toggled in, so KRunner asks again. That trick is the palette's heartbeat, and it breaks when someone types.how-it-works.md · “The palette that pulls”
The window breathesKRunner sizes its window to its rows, so a row that wraps moves the bottom edge. The fix was one-line rows while the agent works, which leaves 40 characters for what the agent is doing.roadmap · MAX_LATEST = 40
Actions are iconsAllow, Always and Deny are three unlabeled icons on a row. One of them reads as “share”, the keyboard path is Shift+Enter, and Enter alone answers nothing.K25 · K22 · usage.md
Consent fatigueA diagnosis asked 10 to 20 times, mostly raw shell a novice cannot judge, so the one dangerous row gets the same click. Wrong words over a right command were also seen: the thesis case.agent-test.md 4, 5 · K5
Two surfaces, two languagesWords in the palette, steps in a TUI docked at the right edge. The panel is the agent's own interface, so the user has to learn two views of one conversation.Meta+A · Meta+Shift+A

Four options, to click through

Each prototype starts paused at the first moment the agent asks. Allow or deny, click the wallpaper to look away, and bring it back with the button below. Restart plays the whole request from the start, in about 15 seconds. A is the chosen direction and opens first. D was added after the first review, for two things the others miss: a conversation that is not gone when you click elsewhere, and a session with some back and forth. It starts in its third turn. Its Ask me switch sets how far you are in the loop, and two more switches sit below the desktop.

Radical ideas that fit any option

These are not windows. They change what the window has to carry, and the first two are in the prototypes.

in C, works in A and B

Consent for a plan, not a command

opencode's read-only plan agent looks first and proposes a list of changes. One Run the plan approves them. kortex already sees every permission request, so it replies once only to a request whose command matches a plan line exactly. Anything else asks as before, and so do root and deletes. This works with Hermes too, since the matching happens in kortex.

in A

Answer from the notification

Freedesktop notifications can carry actions. With Allow once and Deny on the “asks first” notification, the user answers without reopening the palette. That fixes K23 as a side effect, because the notification is closed by its own answer.

idea

Undo instead of ask

Take a snapshot before a change, and ask after the fact for anything that can be rolled back. Debian installs on ext4 by default, so this would need btrfs or a per-file backup. It is out of reach for now, but it is the only idea that removes most rows rather than moving them.

idea

Ask about what is in front of you

Meta+A with text selected, or a window focused, attaches that context: the error dialog, the selected log line. Many problems start in a window, and today the user has to copy them out by hand.

idea

No conversation window at all

Every answer is a rich notification and every consent is a polkit-style dialog. It is the smallest surface possible, but consent then comes from a second place. That brings back the split the panel already has, so it was not prototyped.

idea

Risk words, not risk colours

“Changes your network”, “Deletes files”, “Runs as root” are worked out by kortex from the command, not taken from the model's words. That answers the thesis case: the label stays true even when the explanation is wrong.

Decision: A, the steady palette

kortex stays in KRunner and gives the user more control there. A is cheap to build, needs changes to kortex.py only, and adds no dependency. It also keeps what works today: every search can end with “Ask kortex”. Built as kortex 0.9.0.

  1. Questions as rows. A risk label kortex works out from the command, the agent's words, the command, then Allow this once and Don't, stop here as rows. Always allow is a row with its rule in words, only where it may be offered (K25).
  2. One-line rows while the agent works: the status, its last whole sentence, its steps so far in a word each, and Show every step.
  3. Notifications that answer: Allow once and Deny on the “asks first” notification, which then closes (K23).
  4. An empty Meta+A opens on the hint, the recent conversations and two requests to try (K27).
  5. Allow the rest of this task is off by default. A user turns it on in the palette's list or with patina ai handover on. It covers one request, never what deletes, runs as root, installs or changes a service, and the answer lists what ran on it.

Why off by default. With it, one yes covers commands the user has not seen, and the list of what still asks matches a command's shape, not its effect. That is the weakness the agent test found in Hermes. opencode's point in patina is that nothing changes without a yes that named it, so giving that up is the user's own choice.

Where the build differs from the mock above. The row that asks comes first and the status last, so that Shift+Enter still allows once. The agent's words are one line, not two, because only one-line rows keep KRunner's height. The answer keeps today's twelve lines. The window still changes height when a step asks and when the answer comes. “Five rows, always” did not survive: rows that only filled space were left out.

B, C and D stay on this page as later options. D's session ideas (the conversation that steps aside, earlier turns shortened, the Ask me levels) are the natural next step if users hold sessions of many turns.

Still to see on a real desktop

  • That KRunner keeps the answer rows in order under the row that asks.
  • What Enter does on a row that only says something.
  • That Plasma's notifications show three buttons and close when kortex asks.
  • Whether one approval per plan (option C's idea) is the better hand-over: a yes there covers only commands the user has seen.

Open for the later options

  • D: does “only if risky” ship, and which Ask me level is the default?
  • C: the chip beside the start button or in the tray? Plan-first as default or opt-in?
